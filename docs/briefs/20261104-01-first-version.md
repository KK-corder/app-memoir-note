- **出典**: `/Users/kakeru/Dev/_system/docs/20261029-思い出ノート要件.md`（§2 残したいところ・§3 やりたいこと・§4 守ること。§5 と §3 の答えは 2026-11-04 に本人が回答）。Drive の中の形は `/Users/kakeru/Dev/_system/docs/20261104-思い出ノート-書き出しと取り込み要件.md` §2・§3 が正。本人の依頼「ブリーフをつくって codex に実装させよう」（2026-11-04）

## 目的

本人が毎晩 21 時の知らせから iPhone でアプリを開き、その日の思い出を「問いかけ → 本文と写真」の順に見て、思い出したことをその場で書き足し、写真を足せるようにする。今の ntfy の通知は書き足しにくく、8 月から一度も返事が使われていない。書いた分は Mac（WorkSpace）が取り込んでノートに入れる。アプリは読む・書き足す・写真を足すだけで、ノートの本文を書き換えない。

## 作るもの（WHAT）

App Store に出さない PWA。ビルドなしの素の HTML・CSS・JS（ES モジュール）。GitHub Pages（`https://kk-corder.github.io/app-memoir-note/`）で配信し、Safari でホーム画面に追加して使う。サーバーは置かない。形とログインのお手本は `/Users/kakeru/Dev/4_アプリ/PaperReader/`（`js/login.mjs`・`js/drive.mjs`・`js/storage.mjs`・`js/comments.mjs` の「端末に未送信を残してから Drive に追記する」流れ）。**PaperReader のファイルは読むだけ**で、要るものはこのプロジェクトに写してから直す。

### 1. ログインと Drive

- PaperReader と同じ 2 つの方式（リダイレクト（既定）・ポップアップ）。スコープも同じ `drive.readonly` と `drive.file`
- クライアント ID は `config.js` に置く。値は PaperReader の `config.js` と同じ（同じ Google Cloud のクライアントを使い回す。本人が戻り先の URL を足す）
- 置き場: マイドライブからの道筋（既定 `思い出ノート/_app`。設定で変えられる）。中の `memoir.json` を読み、写真は `photos[].drive_id` で読む（`files/<id>?alt=media` を Authorization ヘッダー付きで取り、Blob の URL にして出す。見えたものから順に読む）
- アプリが書くのは `inbox/` の中だけ（§4）

### 2. 今日の画面（開いたときの画面）

- `memoir.json` の `today` のノートを出す
- **開く前**: `reason`（例「4年前の今日」）・題・日付と、問いかけ（`today.hook`）を大きく出す。場所と一緒にいた人（`meta`）・本文・写真はまだ見せない。「思い出してから開く」のボタンで開く。`hook` が `null` なら問いかけの代わりに「どんな日だった？」を出す
- **開いた後**: `meta`・本文（改行はそのまま）・写真（横に並べて指で送れる。押すと全画面で 1 枚ずつ見られ、閉じられる）・書き足す欄・写真を足すボタン
- 開いたかどうかは `today.date` と `note_id` の組ごとに端末へ覚える。同じ日に開き直したら、開いた後の状態から出す
- `today.date` が今日（日本時間）でなければ、上に「〇月〇日の思い出（Mac の書き出しがまだです）」と出す。それでも見る・書き足すはできる

### 3. 一覧の画面と、ノートの画面

- 全ノートを `date` の新しい順に並べる（`YYYY-MM` だけのものは、その月の 1 日として並べる）。各行は日付・題・写真の枚数
- 上に検索の欄。題・`meta`・本文のどれかに入力した文字を含むものだけを残す
- 押すとノートの画面。今日の画面の「開いた後」と同じ中身（問いかけがあれば上に小さく出す。開く前の段階は無い）。左上に一覧へ戻るボタン
- 画面の下にタブ: 今日・一覧・設定

### 4. 書き足す・写真を足す

- **書き足す**: 複数行の入力欄（2000 字まで。超えたら保存できず、理由を出す）と「書き足す」ボタン
  - 押したら、まず端末に「未送信」として残し（`id` は依頼書 §3-1 の形 `m-<日時>-<4 桁の英数字>`）、入力欄を空にして、本文の下に「追記（Mac に届くのを待っています）」として出す
  - 続けて Drive の `inbox/append_log.json` に追記する（依頼書 §3-1 の形）。ファイルが無ければ作る。アプリが作ったファイルを読み、`entries` の末尾に足して書き戻す。送れたら表示を「送信済み・ノートへの反映待ち」にする
  - 送れなかったら（電波・ログイン切れ・書き込みの許可なし）、端末に残したまま「未送信」と理由を出し、次に開いたとき・「もう一度送る」を押したときに送り直す。同じ `id` を 2 回送らない
  - `memoir.json` の `applied` に `id` が入ったら、その追記の「反映待ち」の表示を消す（本文の末尾に Mac が足した行が出ている）
- **写真を足す**: `<input type="file" accept="image/*" multiple>` で選ぶ
  - 1 枚ずつ、長い辺 2048px 以下・JPEG（品質 0.85）に縮めてから、`inbox/<id>.jpg` として新しく作る。作れたら `append_log.json` に `kind: "photo"` の記録を足す（写真のファイル → 記録の順。記録だけが残って写真が無い、を作らない）
  - 送っている間は進み具合（「2 / 3 枚」）を出す。失敗した写真は理由を出し、端末には残さない（もう一度選び直してもらう）
  - 送れた写真は、その画面を開いている間はその場で小さく出し、「Mac に届くのを待っています」と添える。開き直した後は「写真 n 枚が反映待ち」と数だけ出す（`applied` に入ったら消える）
- 書き込みの許可が無い（403 など）ときは、PaperReader と同じく「もう一度ログインして書き込みを許可してください」と出す

### 5. 設定の画面

- ログイン状態・ログイン・ログアウト（端末のトークンを消す）・ログインの方式
- 置き場の道筋（既定 `思い出ノート/_app`）
- 未送信の追記の件数と「もう一度送る」
- 端末に覚えたもの（フォルダ ID・開いた状態）を消すボタン。**未送信の追記があるときは、消す前に件数を出して確かめる**（未送信は消さない、を既定にする）
- `memoir.json` の `generated` を「いつの書き出しか」として出す

### 6. デモ（確認用）

- `?demo=1` で、ログインも Drive も使わずに `demo/memoir.json` と `demo/photos/*` を読む。画面と操作は本番と同じ
- 書き足す・写真を足すは、デモでは端末の中だけで「送信済み・反映待ち」まで進む（Drive に送らない）
- デモのデータは**すべて作り物**（本人のノートの題・本文・場所・人・写真を入れない）。ノート 8 件以上: 写真 0 枚・1 枚・4 枚以上・`YYYY-MM` だけの日付・`hook` が `null`・長い本文（2000 字以上）・末尾に「日付 追記: 〜」の行があるもの、を含める。`today` は 1 件、`applied` に 1 件以上。写真は依存を足さずに作れる画像（SVG や、スクリプトで作る小さな PNG/JPEG）でよい

### 7. PWA

- `manifest.webmanifest`（`display: standalone`、日本語の名前「思い出ノート」、192/512 のアイコン）と `apple-touch-icon`
- Service Worker はアプリの殻（HTML・CSS・JS・アイコン・デモのデータ）だけをキャッシュする。**Google のドメインへの通信はキャッシュしない・横取りしない**（ノートと写真を端末に溜めない）

## 制約

- 依存: 追加なし（CDN も使わない。Google Identity Services のスクリプトだけは、ポップアップの方式を選んだときに Google から読む。PaperReader と同じ）
- 端末への保存は `localStorage` のキー `memoir-note-v1` 1 つ（トークン・フォルダ ID・開いた状態・未送信の追記・設定）。読み書きに失敗しても落ちない。写真の中身は端末に保存しない
- 文字は `textContent` で入れる（ノートの文字を HTML として解釈しない）
- `fetch` を差し替えられるように持つときは、オブジェクトの持ち物として `this.fetcher(...)` のように呼ばない（iPhone の Safari で止まる。テストの偽の `fetch` は `this` 付きで呼ばれたら投げるものにする）
- 設定の値（クライアント ID・道筋）は起動の関数の引数で差し替えられるようにし、テストは `config.js` の中身に頼らない
- 対象環境: iPhone の Safari（ホーム画面版）。主な幅は 390px の縦持ち。横持ち（844×390）でも崩れない
- 範囲外: `_宿題.md` と「ノートが無い日」の表示・ノートの新規作成・本文の編集や削除・写真の削除・通知（知らせは Mac がリマインダーで出す）・オフラインでノートを読むこと・GitHub への push と公開（Claude がやる）

## エッジ / 落とし穴

- `append_log.json` は**アプリが作ったファイルだけ**に書ける（`drive.file`）。`inbox/` に同じ名前のファイルが複数あるとき・アプリが書けないファイルしか無いときの扱いを決めて、`docs/reports/` の報告に書く（例: 自分が書けるものを使い、書けなければ新しく作る）
- 2 台の端末から同時に書くことは考えなくてよいが、書き戻す直前に読み直して、他の端末が足した `entries` を消さない
- iPhone の写真は HEIC のことがある。`accept="image/*"` で Safari が JPEG にして渡すことが多いが、HEIC のまま来て描けなかったときは「この写真は読めませんでした」と出して飛ばす
- 写真の Blob の URL は、画面から外れたら `URL.revokeObjectURL` で放す（97 件の一覧を行き来してもメモリを溜めない）
- 本文は長い（数千字）ことがある。`white-space: pre-wrap` で折り返し、横にはみ出さない
- 日付の「今日」は日本時間で判定する（端末のタイムゾーンに頼らない）
- 追記の `at` は `+09:00` 付きの ISO 形式（依頼書 §3-1）

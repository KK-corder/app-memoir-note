## 目的

本人が旅行やライブのあと、iPhone のアプリでその場で新しい思い出ノートを作れるようにする。今は Mac で `04_other/旅行とライブ/YYYY-MM-DD_題.md` を手で作るしかない。アプリは追記と同じく `inbox/append_log.json` に「作る」記録を足し、Mac（WorkSpace）がノートのファイルを作る。

## 作るもの（WHAT）

### 1. 入口

- 一覧の画面の上（検索の欄の上か横）に「＋ 新しい思い出」のボタン。押すと作る画面に入る。左上に一覧へ戻るボタン

### 2. 作る画面の項目

| 項目 | 必須 | 中身 |
|---|---|---|
| 題 | ○ | 1 行・40 字まで。前後の空白は取る。`/` `\` と改行は入れられない（入れたら理由を出す）。`_` `.` で始められない |
| 日付 | ○ | 3 つから選ぶ: **1 日**（既定。今日の日本時間を初期値）・**月だけ**（「日は覚えていない」）・**期間**（始まりと終わりの日。終わりは始まりより後） |
| 場所 | | 1 行・60 字まで。打つと、これまでのノートの場所の候補が出る（§3） |
| 一緒にいた人 | | 1 人ずつ足す（足した人は小さな札で並び、× で外せる）。打つと、これまでのノートの人の候補が出る（§3）。1 人 20 字まで・`・` `/` は名前に入れられない |
| 本文 | | 複数行・10000 字まで |
| 写真 | | 今の「写真を足す」と同じ選び方・縮め方（長い辺 2048px 以下の JPEG）。作る画面では選んだ写真を小さく並べて出し、× で外せる |

- ボタン「作る」。必須が欠けている・字数を超えている・同じノートがある（§4）ときは押せないか、押したら理由を出す
- **下書き**: 打った文字（写真以外）は端末に下書きとして残し、作る画面を出て戻っても、再読み込みしても続きから書ける。「作る」を押して受け付けたら下書きを消す。下書きを捨てるボタン（押したら確かめる）。写真は下書きに残さない（出たら外れる、と画面に一言出す）

### 3. 候補

- `memoir.json` の各ノートの `meta`（「日付 / 場所 / 一緒にいた人」。4 つ目以降の欄があれば無視）から作る
  - 場所: 2 つ目の欄
  - 人: 3 つ目の欄を `・` と `、` で分けたもの
- 多く出てくる順に並べ、打った文字を含むものだけを 8 件まで出す。候補を押すとそのまま入る。候補に無い名前も自由に打てる
- 候補は Drive から読んだ `memoir.json` からその場で作り、端末に保存しない

### 4. ノートの名前と 3 行目（Mac 側の依頼書 §2 と同じ形）

- `note_id`（ファイル名から `.md` を除いたもの）:
  - 1 日: `YYYY-MM-DD_題`
  - 月だけ: `YYYY-MM_題`
  - 期間: 始まりの日で `YYYY-MM-DD_題`
- 3 行目（`meta`）: `<日付> / <場所> / <人を「・」でつないだもの>`
  - 日付の書き方: 1 日 `2026.11.08`・月だけ `2026.11`・同じ月の期間 `2026.11.08-10`・月をまたぐ期間 `2026.10.30-11.02`・年をまたぐ期間 `2026.12.30-2027.01.02`
  - 場所や人が空でも欄は残し、「不明」などで埋めない（例 `2026.11.08 /  / `。区切りの ` / ` は必ず 2 つ）
- `memoir.json` の `notes` に同じ `id` がある・端末の反映待ちに同じ `note_id` があるときは作れない（「同じ日付と題のノートがあります。題を変えてください」）

### 5. 送る流れ（今の追記と同じ考え方）

- 「作る」を押したら、`kind: "create"` の記録を端末に「未送信」として残し（`id` は今の `m-<日時>-<4 桁の英数字>`）、続けて `inbox/append_log.json` に足す。形は依頼書 §2:
  ```json
  { "id": "m-2026-11-08-213000-ab12", "kind": "create", "note_id": "2026-11-08_紅葉の山歩き", "title": "紅葉の山歩き", "meta": "2026.11.08 / 架空山 / 友人A・友人B", "body": "本文", "at": "2026-11-08T21:30:00+09:00" }
  ```
- `create` の記録が**送れてから**、選んだ写真を今の `kind: "photo"` と同じ手順で送る（`note_id` は新しいノートの `note_id`。`append_log.json` の中で `create` より後ろに来る）。写真の送信中は「2 / 3 枚」の進み具合を出す
- `create` が送れなかったら（電波・ログイン切れ・書き込みの許可なし）、記録は端末に未送信のまま残し、今の追記と同じく次に開いたとき・「もう一度送る」で送り直す。選んだ写真はそのとき送れないので、「写真は、ノートが届いてからノートの画面で足してください」と出す（写真の中身は端末に保存しない、を守る）
- 同じ `id` を 2 回送らない。設定の画面の「未送信の件数」に `create` も数える。端末のデータを消すときの確かめ（未送信は消さない）にも含める

### 6. 反映待ちのノート

- `memoir.json` に入るまで、作ったノートを一覧に出す（`date` の位置。行に「Mac に届くのを待っています」の印）。押すとノートの画面で題・`meta`・本文が見える（端末に残した `create` の記録から出す）
- 反映待ちのノートの画面で:
  - `create` が**未送信**の間は、書き足す・写真を足すを押せない（「ノートを送ってから書き足せます」）
  - `create` が**送信済み**なら、書き足す・写真を足すを今の流れで使える（記録は `create` より後ろに入るので、Mac は順に取り込める）
- `memoir.json` の `applied` に `create` の `id` が入ったら、端末の記録を消し、`memoir.json` のノートを出す（今の reconcile と同じ）
- `memoir.json` の `rejected`（依頼書 §2-3。無ければ空とみなす）に `create` の `id` があれば、そのノートの行と画面に「Mac で作れませんでした: `<reason>`」を出し、端末の記録は消さない。ノートの画面に「本文を写す」（クリップボードに題・3 行目・本文を入れる）と「この記録を消す」（押したら確かめる）を出す

### 7. デモ

- `?demo=1` で作る画面も同じように動く（Drive に送らず、端末の中だけで「送信済み・反映待ち」まで進む）
- `demo/memoir.json` に、候補が分かるだけの作り物の場所・人を足す（同じ人が何件かに出るように）。`rejected` の例を 1 件入れる（それに当たる `create` は端末に無いので画面には出ない。形を読めることの確認だけ）。**本人のノートの題・場所・人は入れない**

## エッジ / 落とし穴

- 題には絵文字や全角記号が入る。字数は今の `textLength` と同じく見た目の文字で数える
- `<input type="month">` は iPhone の Safari で使えるが、デスクトップの一部のブラウザでは文字の欄になる。値が `YYYY-MM` でなければ理由を出す
- `memoir.json` の `meta` は終わりの空白が取れていることがある（場所と人が空のノートは `2026.11 /  /`。WorkSpace の 11/8 のテストで確認）。`/` で分けて各欄の前後の空白を取り、空の欄は候補にしない（` / ` で分けると場所が「/」になる）
- 候補はノート 97 件ほどから作る。打つたびに作り直しても重くないが、`memoir.json` を読み直したときに作り直す
- 反映待ちのノートを開いている間に `applied` に入ったら、同じ画面のまま `memoir.json` のノートに切り替わってよい（戻る位置を失わない）
- 日付の「今日」は日本時間（今の `japanDate`）
- `append_log.json` の書き戻し前に読み直して、他の端末が足した `entries` を消さない（今と同じ）

# 設計判断の記録

あとから「なぜこうなっているか」を、別のセッションや別のエージェントが再検討せずに済むように残す。
書くのは、選択肢があって1つに決めたことだけ（実装の細部は書かない）。新しいものを上に追記する。

書き方:

```
## YYYY-MM-DD <決めたこと>
- 決定: 
- 理由: 
- 却下した案: （あれば、なぜ却下したか）
- 決めた人: ユーザー / Claude（ユーザー確認済み）
```

## 2026-11-08 新しい思い出の記録の形・送る順番
- 決定: 新しい思い出は `append_log.json` の記録 `kind: "create"`（`note_id`・`title`・3 行目の `meta`・`body`）として送り、Mac がファイルを作る。3 行目はアプリが組み立てる（日付は `2026.11.08`・`2026.11`・`2026.11.08-10` など今のノートの書き方）。写真は `create` が送れてから送り、`create` が未送信の間はそのノートに書き足せない。Mac が作れなかったものは `memoir.json` の `rejected` で返す。日付は「1 日・月だけ・期間」、場所と人は自由に打てて今のノートから候補を出す。
- 理由: Mac は記録を上から順に取り込むので、写真と追記が `create` より後ろにあれば行き先のノートが必ずある。3 行目の形をアプリ側だけに持たせると、Mac は書くだけで済む。候補は表記をそろえるため（今のノートは人を「・」で区切っている）。日付と候補は本人が選んだ（11/8）。
- 却下した案: 写真を作る画面で端末に残しておく（写真は端末に保存しない、を崩す）。Mac が `title` などから 3 行目を組み立てる（形が 2 か所に分かれる）。同じ名前のノートがあれば Mac が別名で作る（アプリが知っている `note_id` とずれ、後ろの写真が迷子になる）。
- 決めた人: ユーザー（日付の選び方・候補）／Claude（記録の形・順番・`rejected`）

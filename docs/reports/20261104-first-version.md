- `icons/icon-192.png`・`icons/icon-512.png`・`icons/apple-touch-icon.png`: 標準 Python だけで生成したノートのアイコン。
- `manifest.webmanifest`・`sw.js`: standalone、相対パス、版付きの殻キャッシュ。Google の通信は対象外。
- `tests/index.js`: 指定の `node --test tests/` 用入口（この環境の Node v25.9.0 ではディレクトリ指定に入口が必要）。

## ブリーフとの差異・仮定

- `append_log.json` は、`isAppAuthorized`・`capabilities.canEdit` と、本アプリが作成時に付ける `appProperties.memoirNote = memoir-note-v1` を全て確認してから更新する。同名が複数なら選択せず停止する。書けないものしかない場合も、重複ファイルを新しく作らず停止し、指定の再ログイン案内を出す。ログを自動で削除・置換しない。重複や別の作成元が原因の場合は、再ログインだけでは解消しないので Drive 側の確認が必要。
- `思い出ノート/_app` と `inbox/` は依頼書どおり Mac が作る前提。存在しない場合は理由を出し、アプリからフォルダを作らない。
- 写真の作成後にログ追加が失敗した場合は、inbox に記録と結びつかない JPEG が残り得る。削除は禁止のため自動削除はしない。画面には失敗理由と選び直しの案内を出し、端末には写真本体も未送信の写真記録も残さない。
- 「端末に覚えたものを消す」は未送信を常に保持し、追記や反映待ちを削除する選択肢は付けていない。
- 追記の字数は Unicode コードポイントで数える（絵文字 1 コードポイントは 1 字）。日本時間の at は例に合わせて秒単位・`+09:00`。
- デモの today は固定の 2026-11-04。後日に開けば仕様どおり古い書き出しの案内が出る。デモ・本番・各 Drive 道筋の追記と開いた状態は、同じ保存キー内で分離する。
- `node --test tests/` は最初に Node のディレクトリ解決で失敗したため `tests/index.js` を設置し、指定コマンドのまま通るようにした。依存追加はない。

自己レビューで重点的に見た箇所は「保存/送信が途中まで成功した直後の再読み込み」と「写真を処理中に別画面へ移動する場合」。どちらも専用の回帰テストを追加し、重複防止、入力保持、Blob URL 解放、移動先の写真選択欄の再有効化を確認した。

PaperReader は参照・コピーのみ。WorkSpace と Pictures は読み書きしていない。ブラウザ起動、ネットワークアクセス、依存追加、ファイル削除、コミット、push、公開は実施していない。
